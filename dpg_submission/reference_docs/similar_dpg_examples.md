## What To Learn From These Profiles

1. Registry pages distinguish verified indicators from self-reported indicators.
2. Indicator 8, platform independence, privacy/legal, and do-no-harm sections are often self-reported, so Air for Tomorrow should use clear, evidence-backed claims.
3. Profiles list assessed repositories/components; Air for Tomorrow should clearly identify the repository and pretrained model artifact in scope.
4. Scale information is self-reported and should be accurate, restrained, and public-safe.
5. Standards and best-practices claims should be specific to actual documented implementation.
